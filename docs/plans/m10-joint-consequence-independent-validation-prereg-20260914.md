## 独立验证设计与资源上限

- 使用全新父 tape：16 个，来源为与开发数据不重叠的 `test` tape，`base_seed=293001`，仅作为独立同分布验证，不作 OOD 搜索。
- 每个父 tape 预先定义 prefix length `[1, 2, 3, 4]`；不按结果筛选父 tape、前缀或任务。
- 每个前缀最多 25 个合法候选，仅用于候选集合和模型/基线选择；直接后果评估只运行四种方法各自选出的动作。
- 每个方法和每个前缀使用 8 次配对外生重复；`ideal` 与 `composite`（冻结弱通信）分别运行。
- 最多计划 128 个父 tape×条件×前缀单元、4096 条已选动作分支（16×2×4×8×4），不扩展为全候选×重复搜索；不足时报告实际分母。
- 所有方法在同一条件、同一前缀、同一 repeat 使用相同 branch exogenous key；方法名不进入该 key。前缀回放使用独立 prefix key，候选分支仅在公开状态冻结后切换 key。运行前保存 tape、参数、源码和输入哈希。

## 预先冻结的判断

主指标是每个前缀/重复固定任务集合中，模型选中动作与公开联合基线选中动作的 `on_time_count` 配对差；正式汇总以父 episode 为统计单位，分别报告 ideal 和 weak，不把候选、前缀或重复当独立父样本。次指标为相对原规则、零差值平局规则的差，以及 deadline failure、删失、终态覆盖、安全和通信/计算成本。

- 先报告全部预定前缀；无公开 pending 任务集的单元标记不适用，不算成功或失败。
- 仅在候选分支和参考分支的固定任务集合均观察到 deadline 结局时计算完整配对后果差；否则保留删失原因并给出有效分母/必要时保守界。
- 同差异组、全平局组、部分并列最优组和删失组分层报告；有限重复中的事后最佳分支只作诊断。
- 安全违规为必要门槛；未登记业务成本阈值，因此即使点估计改善也不能自行宣布正式通过。点估计改善但父级不确定性较大，结论为证据不足。
- 若模型不超过公开联合基线，停止当前融合路线；若改善仅来自平局规则，单独标注；若出现 deadline 或安全代价，保留权衡，不扩样。

本验证最多回答“固定公开续行控制器下，冻结模型是否有独立候选选择价值”。无论结果如何，不能外推为 GPPO 融合收益、全 episode 收益或弱通信可用性通过。
