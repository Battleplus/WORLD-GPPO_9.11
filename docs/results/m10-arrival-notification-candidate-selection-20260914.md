## 结论先行

当前仿真工程候选为：**原调度器 + `bounded_retry` 完成通知**。这只是可继续观察的工程候选，不是默认生产配置，也不是弱通信可用性或正式业务验收通过。已知回归 tape 上按时主机确认从 9/96 增至 21/96，但按时物理到达从 48/96 降至 46/96，通信代理字节量增加；本轮没有真正独立验证集，成本门槛也尚未由业务方确认。

`arrival-slack` 调度器及其与通知的 `combined` 方案不作为默认候选：弱通信下按时物理到达分别为 32/96 和 31/96，较原系统 48/96 明显下降。实现、配置、ledger 和负结果均保留。

### 通知成本与路径

composite 下，通知改进的46个物理到达任务产生92次完成通知传输尝试：初次46次（23 sent、23 dropped），重试46次（28 sent、18 dropped）。通知状态：sent 51、dropped 41、received 29、expired 17、duplicate-ignored 4、身份拒绝1；完成 ACK 为 received 30、dropped 3，重试发送28次。

新增完成通知与 ACK 的序列化代理字节量为 33,064 + 5,018 = **38,082 bytes**。全通信代理字节量为原系统 5,899,716、通知改进 6,354,451，增加 **454,735 bytes**。这不是实网流量；差额还受通知到达时序、公开状态和控制流变化影响，不能全部归因于通知载荷。

完整决策墙钟样本：原 composite `n=256`、均值2.023146 ms、P95 3.417775 ms、最大8.4363 ms；通知 composite `n=271`、均值1.397569 ms、P95 1.8456 ms、最大2.3196 ms。样本数和控制流不同，不能据此宣称稳定计算加速。

相对原 composite，按时主机确认的15个救回任务为：

`2093001/task-1`、`2093002/task-0`、`2093002/task-5`、`2093003/task-4`、`2093005/task-0`、`2093008/task-5`、`2093009/task-0`、`2093009/task-4`、`2093010/task-5`、`2093013/task-1`、`2093013/task-5`、`2093014/task-1`、`2093014/task-4`、`2093015/task-0`、`2093016/task-3`。

3个新增损失为：`2093007/task-4`、`2093010/task-1`、`2093011/task-5`。物理到达没有救回任务，并有2个损失：`2093004/task-5`、`2093011/task-5`。

这些逐任务差异证明净变化，但不单独证明每个任务的因果归属。通知合法接收后更新公开任务视图，进而影响后续调度；因此物理损失是可观测控制流副作用，不能预先解释为通知拥塞，也不能把15个救回全部归因于重试。

旧原系统 ledger 的26个物理到达任务没有 `completion_message_id`，旧丢弃记录也没有 `message_kind`，无法严格拆出“生成后丢弃”和“生成记录缺失”。源码虽在到达时先创建完成记录再发送，但这不能替代逐条证据，旧值和不确定性保留。

### 随机序列、共享链路与身份边界

通信故障由带消息身份的确定性哈希 profile 计算，不是全局顺序 RNG；新增通知不会仅因调用次数改变而重排相同消息的故障结局。可靠通知使用独立的逻辑 `completion_notice` / `completion_ack` 链路和独立待发队列，本次没有证据表明它与普通 telemetry 共享同一物理队列。

但独立逻辑通道不是免费的真实物理链路：通知尝试、重试、丢弃、ACK 和代理字节均已计账，合法接收后的公开状态还会影响后续动作。故通信成本可测，但系统级因果分离有限；不能把差异写成纯协议收益或纯拥塞效应。

## 3. 调度方案为何不采用

旧 ledger 中20个 `scheduling_no_selection` 任务全部存在 `first_legal_candidate_time`，说明当时至少有合法公开候选；首次合法时刻有19次选择其他任务、1次 NOOP，其中14次其他任务命令 accepted，3次 task unavailable，1次 resource unavailable，1次 resource busy，1次 NOOP。这支持检查待办任务竞争/选择排序，但不证明换一个控制器就必然可行。

同一开发回归集 composite 下：

- `arrival-slack`：物理到达救回9、损失25，净 `-16`；按时主机确认救回1、损失4，净 `-3`；
- `combined`：物理到达救回9、损失26，净 `-17`；按时主机确认救回10、损失5，净 `+5`。

两者均无新增安全违规，但物理任务效果退化，故不作为默认。这个结果不是“规则必然不可行”的证明，也不支持把未选择任务直接当作可学习错误。

## 4. 当前候选决策

| 方案 | 状态 | 依据 |
|---|---|---|
| 原调度器 + 单次通知 | 历史对照 | 弱通信按时确认 9/96；保留为基准 |
| 原调度器 + `bounded_retry` 通知 | **当前仿真工程候选** | 确认 9→21；ideal 不退化；但 composite 物理 48→46、代理通信量增加，独立验证和成本门槛缺失 |
| 原调度器 + `arrival-slack` | 不采用默认 | 物理 48→32，负结果 |
| `arrival-slack` + `bounded_retry` | 不采用默认 | 物理 48→31，负结果 |

由于独立证据尚未完成且成本门槛未定义，`bounded_retry` 仅保留为候选，不宣称整体可用性通过。`physical_arrival` 与 `host_confirmation` 继续分开报告，迟到通知只能增加“已获知物理事实”，不能倒改按时确认指标。

## 5. 阶段研究结论与下一问题

已有候选后果模型训练过 travel、service、energy、deadline 等头；在旧持续服务协议/Graph-5/25-action 版本上，部分 test 指标相对简单基线改善（travel MAE 0.2973 对 0.3896；failure Brier 0.0389 对 0.0414），但 deadline/OOD 和候选选择稳定性没有形成完整证据，最终没有建立策略调度增益。旧模型路线的负结果冻结，不因通知收益改写。

本轮通知收益是协议工程收益，不是世界模型贡献。调度负结果说明单任务局部余量不足以代表全局任务竞争、机会成本、资源占用和通信后果。未来若恢复世界模型研究，只提出一个可证伪假设：

> 在相同合法公开状态下，预测“选择一个候选后对任务集合的联合后果”（含机会成本、资源占用和通知可达风险）的模型，相对原规则、GPPO 和 GPPO-History，能在父 tape 分组的独立测试集上改善候选选择，同时不降低物理到达、满足固定通信/计算成本上限，并通过相同安全门禁。

所需证据是独立父 tape 的候选排序、选中动作真实后果、物理到达与主机确认、成本和安全的配对结果；不能把单任务误差或系统总能耗误差替代这些证据。本阶段不生成新数据、不训练、不恢复旧融合矩阵。
